# SteamOS Release Runbook

SteamOS release artifacts are generated by `steam/steamos/scripts/package-steamos.sh` and checked by `steam/steamos/scripts/verify-steamos-release.sh`.

## Build And Package

Development package:

```sh
bash steam/steamos/scripts/package-steamos.sh
```

The script builds `qlinkd` and `qlinkctl`, stages the package payload, writes `dist/steamos/quantumlink-steamos-<version>.tar.zst`, and creates sidecar files in `dist/steamos/quantumlink-steamos-<version>/`:

- `SHA256SUMS.txt`
- `SBOM.spdx.json`
- `release-manifest.json`
- `verify-report.json`
- `quantumlink-steamos-<version>.tar.zst.dev.sig` for dev packages

The archive payload includes:

- `bin/qlinkd`
- `bin/qlinkctl`
- `scripts/install-steamos.sh`
- `packaging/systemd/qlinkd.service`
- `packaging/systemd/qlinkd.service.d/activate-network.conf.sample`
- `config/config.example.json`
- `config/games/*.toml`
- SteamOS readiness and release docs when present

To package prebuilt binaries:

```sh
QLINK_STEAMOS_BIN_DIR=/path/to/bin \
QLINK_STEAMOS_SKIP_BUILD=1 \
bash steam/steamos/scripts/package-steamos.sh
```

## Production Signing

Dev packages use a classical SHA-256 attestation and are always marked `notProductionReady`.

Production packaging requires `QLINK_STEAMOS_SIGNING_MODE=production` plus either:

- `QLINK_STEAMOS_SIGNATURE_FILE=/path/to/quantumlink-steamos-<version>.tar.zst.sig`
- `QLINK_STEAMOS_RELEASE_PRIVATE_KEY=/path/to/ed25519-private-key.pem`

The verifier validates production signatures with:

```sh
QLINK_STEAMOS_RELEASE_PUBLIC_KEY=/path/to/ed25519-public-key.pem \
bash steam/steamos/scripts/verify-steamos-release.sh dist/steamos/quantumlink-steamos-<version>.tar.zst
```

Publication gates should add:

```sh
QLINK_STEAMOS_REQUIRE_PRODUCTION_READY=1
```

## Verification

Run the standalone verifier:

```sh
bash steam/steamos/scripts/verify-steamos-release.sh dist/steamos/quantumlink-steamos-<version>.tar.zst
```

The verifier checks expected files, executable bits, checksums, manifest artifact hashes and sizes, production signature status, secret-like paths/content, and installer shell syntax.

Dev signatures are valid for development inspection only. A report with `"notProductionReady":true` must block production publication.
